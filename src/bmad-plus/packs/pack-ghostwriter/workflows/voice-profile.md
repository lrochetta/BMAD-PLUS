# Voice profile

Read the [editorial contract](../shared/editorial-contract.md). Use `ghostwriter-voice` for this workflow.

## Inputs

Identify the voice owner, intended audience, locale, channel, existing profile version, and which examples the owner has approved for this purpose. Use preferences already supplied. Keep a private sample in its authorized location.

## Procedure

1. Inspect each approved sample in context. Record its reference and digest when available, channel, audience and a short passage locator. Separate explicit instructions from observations about the sample and from judgments still awaiting confirmation.
2. Compare how the author handles the same task in different situations. A brief answer to a colleague and a notice to a new customer can justify different forms of address. Record competing observations with their contexts. A single example supports a tentative observation.
3. Write actionable preferences, exceptions and confidence in the profile. A preference such as “say who checks the invoice before giving the deadline” can be applied to a new topic. A date or promise in the example belongs to that example.
4. Try the profile on a short passage from the current brief. Check facts against that brief. If examples are unavailable, use explicit preferences only and identify what remains uncertain.
5. When storage is authorized, create a new version in the project-owned profile area. Preserve prior versions and their sample references. Apply a requested one-off correction to the current draft. Promote it to a reusable rule only when the owner has requested that scope.

## Delivery

Provide the profile version, its applicable channels and locales, and the few preferences which change the next draft. Include unresolved choices separately. If the input's provenance is unclear, ask for an approved example before claiming to have learned that voice.
