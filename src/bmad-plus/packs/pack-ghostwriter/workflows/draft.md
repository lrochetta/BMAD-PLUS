# Draft

Read the [editorial contract](../shared/editorial-contract.md). Use `ghostwriter-write`. Choose additional editing only when the draft needs it.

## Inputs

For a narrative brief whose author requests a debate on story structure, consult the [narrative council](../workshops/council/README.md) before outlining. Carry the author's chosen direction into the draft.

Start with the existing brief, intended recipient, reader task, format, language, usable sources and any approved profile. Recover known details from the project. Ask a focused question when a missing fact determines the substance of the answer.

## Procedure

1. Note what the reader needs to decide, know or do. Assemble the usable facts and their sources. Mark unknowns that could affect the decision. Use voice samples solely for expression.
2. Choose the opening and order for this reader. A status reply can begin with the actual status. A procedure should introduce a prerequisite before the action which depends on it.
3. Draft with `ghostwriter-write`, using the language, register and length appropriate to the channel. Preserve required wording and links. Use a list when it makes actions easier to follow. Stop once the reader has the information needed.
4. Check each new claim, example, commitment and call to action against the brief. For example, “the team expects a decision on Monday” supports reporting that expectation. It gives no basis for promising shipment on Monday.
5. Read the text once as the recipient. Correct a confusing transition or repetitive passage in place. Compare the final draft with the brief using `ghostwriter-verify`. Refer unresolved technical claims back to the responsible author.

## Delivery

Return the draft in the requested form. Put material unknowns in a separate note, and identify the passage affected. When the missing answer makes a public statement unusable, deliver the supported portion as a draft for review.
