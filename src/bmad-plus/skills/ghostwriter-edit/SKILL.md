# Edit for the reader's task

Open the Ghostwriter pack beside the installed skills. Read its [editorial contract](../pack-ghostwriter/shared/editorial-contract.md). The [improve workflow](../pack-ghostwriter/workflows/improve.md) describes the full task. In a source checkout these resources live in `../../packs/pack-ghostwriter/` under the same relative names. If a required resource is missing, identify its path before proceeding.

1. Read the original from beginning to end. Identify its intended result, reader, channel and permitted depth of editing. For reader feedback alone, annotate the original and return the findings without changing it.
2. Map each section to the question it answers. Identify repeated explanations, missing prerequisites, assertions without support and exceptions placed too far from the rules they qualify.
3. Work on the smallest unit that solves each problem. Move a prerequisite before the step that needs it, bring a condition next to its promise or merge two paragraphs that make the same claim. Preserve the relationship between reasons, outcomes and exceptions when rearranging them.
4. Develop a point only from material supplied for this purpose. Record the evidence for substantive additions and the reason for meaningful cuts. Where an unsupported claim needs an owner's decision, flag the passage and the specific missing evidence.
5. Compare original and revision, including headings, links and transitions after a move. Confirm the requested action and its conditions still mean the same thing. Deliver the revised copy and, where requested, a separate account of significant changes and unresolved questions.

For a returns page with a twenty-day window in the opening and an exception for personalized items in the footer, move the exception beside the eligibility rule. Leave the start date of the twenty days open if the source never defines it.
