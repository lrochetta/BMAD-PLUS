# Build a voice profile

Open the Ghostwriter pack beside the installed skills. Read its [editorial contract](../pack-ghostwriter/shared/editorial-contract.md). The [voice-profile workflow](../pack-ghostwriter/workflows/voice-profile.md) describes the full task. In a source checkout these resources live in `../../packs/pack-ghostwriter/` under the same relative names. If a required resource is missing, identify its path before proceeding.

1. Identify whose voice is wanted, the audience, language variant and channel. Reuse an approved profile for that combination when available. For a one-off instruction, apply it to this piece and leave the stored profile alone.
2. Ask for an approved excerpt when examples would resolve a material uncertainty. With preferences alone, record them as explicit preferences and leave observations about the author's habits open. Keep samples in their authorized location. Use their references, versions and fingerprints when the profile format requires them.
3. Compare passages that perform similar jobs. For each useful observation, note the passage, the choice the author made, the setting in which it works, confidence and any conflicting example. Give the author's explicit preference priority over an inferred habit.
4. Test the profile on a passage from the new brief. Carry across choices such as how the author introduces a decision. Take every new factual claim from the new brief or an authorized source. A sample's anecdote, credentials, preference or quotation belongs to its original context.
5. Deliver the profile with its scope, version, source references and uncertain observations. Save a project profile only when the user has authorized that write. A lasting correction gets a new version with its reason and predecessor. Preserve earlier profiles and keep generated drafts out of the sample set unless explicitly approved as examples.

An editor supplies two status emails beginning with the decision and one formal grant letter beginning with context. Record the decision-first preference for status emails. The grant letter supports a different convention for that audience.
